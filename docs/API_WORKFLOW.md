# Local Project API and Workflow — Phase 1

## Start

```powershell
npm run api -- --workspace D:\AIAutoSlidesData --port 8787
```

The API binds only to `127.0.0.1`. It needs Node.js 22.5+ for the built-in `node:sqlite` module. It uses no network research service, paid API, or credential until an outbound action is explicitly enabled. The database is `<workspace>/db/aiautoslides.sqlite`; the server creates `incoming/`, `source-blobs/`, `runs/`, and `assets/commons/` beside it.

## Routes

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/health` | Local service status |
| `POST` | `/research/search` | Opt-in scholarly metadata search through OpenAlex, Crossref or arXiv; body must include `allow_network:true` |
| `POST` | `/projects/{id}/research/search` | Same explicit search opt-in, saving returned candidates to that project's local candidate list |
| `GET` | `/projects/{id}/research/candidates` | List saved candidate metadata and whether each has been registered as a source |
| `POST` | `/projects/{id}/research/candidates/{source_id}/import` | Register one saved candidate as an unverified project source; does not create evidence |
| `GET` | `/projects/{id}/evidence` | List exact source excerpts attached to the project and their review states |
| `POST` | `/projects/{id}/evidence` | Add a user-supplied excerpt and locator as `pending`; request fields cannot promote it to verified |
| `POST` | `/projects/{id}/evidence/{evidence_id}/review` | Record a caller-supplied human decision (`verified` or `contradicted`) for the excerpt's current content hash |
| `GET`, `POST` | `/projects` | List projects; create from `{title, presentation_ir}` |
| `GET`, `POST` | `/profiles` | List or create local preference profiles |
| `GET`, `PATCH` | `/profiles/{id}` | Read or replace preferences on one local profile |
| `GET` | `/projects/{id}` | Project metadata, IR revision hash, sources and current Presentation IR |
| `POST` | `/projects/{id}/sources` | Import `{source_id, file_path, type?, locator?, verification_status?}` from `<workspace>/incoming/` |
| `POST` | `/projects/{id}/research/jobs` | Queue an opt-in scholarly metadata search as a durable job |
| `POST` | `/projects/{id}/research/papers` | Queue download and local extraction of one explicitly selected arXiv candidate (`{source_id, allow_download:true}`) |
| `POST` | `/projects/{id}/research/documents` | Queue PDF.js, DOCX, Docling, or MarkItDown extraction for one imported source (`{source_id, allow_extract:true, engine?:"pdfjs"|"docling"|"markitdown", allow_model_download?:boolean}`) |
| `POST` | `/projects/{id}/research/pages` | Queue a one-page Crawl4AI job for an operator-authorized public HTTPS URL (`{source_id, url, allow_network:true, site_authorized:true}`) |
| `POST` | `/projects/{id}/assets/commons` | Queue one selected Wikimedia Commons image download (`{candidate, asset_id, allow_network:true, allow_download:true}`) |
| `GET` | `/projects/{id}/slides` | Ordered slide IR rows |
| `GET`, `PATCH` | `/projects/{id}/slides/{slide_id}` | Read a slide; patch `title`, `assertion_title`, `speaker_notes`, `evidence_ids` or `elements` |
| `POST` | `/projects/{id}/assets/{asset_id}` | Authenticated mode: upload bounded PNG/JPEG/SVG bytes with `x-source-id`, `x-media-type`, and `x-license` headers |
| `GET`, `POST` | `/projects/{id}/jobs` | List jobs; enqueue a render workflow (optional `{preview:false}`) |
| `POST` | `/projects/{id}/source-files/{source_id}` | Authenticated mode: import bounded raw bytes; optional `x-filename`, `x-source-type`, and `x-source-locator` headers |
| `GET` | `/jobs/{id}` | Durable status, stage events, result or failure |
| `POST` | `/jobs/{id}/cancel` | Cancel queued work or request cancellation at the next stage boundary |
| `GET` | `/projects/{id}/artifacts`, `/jobs/{id}/artifacts` | List project/job artifacts with hashes |
| `GET` | `/artifacts/{id}` | Download an artifact after SHA-256 verification |

API project/job/artifact IDs are generated by the server. A slide PATCH creates a new content-addressed IR revision. It does not overwrite previous IR or PPTX files; enqueue a new job to render it. Full-deck regeneration is used, and unchanged-slide hashes are not guaranteed.

## Workflow stages

1. Validate the supplied Presentation IR and record its slide/source counts.
2. Inventory source verification states. This stage explicitly reports `performed:false`; it does not do web research or verify facts.
3. Create a deterministic slide takeaway/evidence-reference plan from supplied IR.
4. Probe and negotiate PptxGenJS capabilities against requested PPTX/native-chart requirements.
5. Generate editable PPTX and run OOXML/data QA.
6. Render PDF/PNG previews with the existing PowerPoint/Poppler preview script, unless `preview:false`.
7. Record structural findings, leave scientific accuracy `not_assessed`, and leave visual review `pending_human`.
8. Export copies of artifacts and persist a workflow report, JSONL stage log, hashes and SQLite artifact rows.

The project/render workflow is local-only. The separate `/research/search` route sends the query to the selected public metadata provider only when `allow_network:true` is present. Project-scoped search does the same and saves the returned candidate metadata locally. A later explicit import registers one selected candidate in `source_ir.sources` with `verification_status:unverified`; it does not create evidence records or verify claims. Users may add an exact source excerpt and locator through `/evidence`; the API always records new excerpts as `pending`. For supported UTF-8 text files, selectable-text PDFs and DOCX files imported into the local API workspace, evidence responses report whether the excerpt occurs verbatim in the immutable source bytes or extracted page/paragraph text. By default scanned PDFs return `pdf_ocr_disabled`; the API CLI can explicitly enable offline OCR with `--enable-local-pdf-ocr` and an optional bundled language selection. OCR matches use the separate `ocr_match`/`ocr_no_match` states and confidence metadata; they do not prove the OCR text appears in the original bytes, prove claim support, or change verification state. A reviewer can then submit a verified/contradicted decision with the content SHA-256 returned by the API. If a later IR update changes the reviewed excerpt, source ID or locator, the old decision is retained for audit but becomes stale and the evidence returns to `pending` until reviewed again. The service records reviewer text and time without authenticating the reviewer, evaluating entailment, or changing the parent source status. Search results remain unverified metadata candidates. Restart recovery marks interrupted `running` jobs failed with an explanation and dispatches queued jobs; it does not pretend interrupted renders completed. PptxGenJS cannot be safely interrupted during its in-process render call, so cancellation takes effect at workflow stage boundaries.

Scholarly search jobs persist their provider/query parameters, status, stage events and normalized unverified source candidates. A queued search resumes after API restart; an interrupted running request is marked failed by the same recovery policy. After selecting one arXiv candidate, `POST /projects/{id}/research/papers` requires `allow_download:true` and queues a durable single-paper job. It downloads at most one 50 MiB PDF from the arXiv host allowlist, extracts text locally with PDF.js, stores the original PDF by SHA-256 and attaches page-located excerpts as `pending` evidence. PDF, extracted Markdown, manifest and evidence JSON are job artifacts. Excerpts remain unverified and paper-specific reuse rights remain `needs_review`. This does not constitute a multi-provider research DAG.

For a source already imported into the workspace, `POST /projects/{id}/research/documents` requires `allow_extract:true`. By default it queues local PDF.js selectable-text extraction or DOCX paragraph extraction. Set `engine:"docling"` to run the pinned local Docling worker asynchronously for an imported PDF/DOCX; model downloads stay disabled unless the caller separately sets `allow_model_download:true`. That opt-in may download model weights from their configured host, but the source document remains local. Set `engine:"markitdown"` to use the optional isolated MarkItDown 0.1.9 environment; this conversion is local-only, cancellable and limited to document-level paragraph locators. The API checks the immutable content-addressed source after parsing. All modes create Markdown, manifest and evidence JSON artifacts, with excerpts attached as pending evidence. Unsupported formats, unavailable optional parser runtimes, scanned-only PDFs under PDF.js and malformed documents fail with an actionable job error; extraction never verifies scientific claims.

`POST /projects/{id}/research/pages` requires both `allow_network:true` and `site_authorized:true`, plus a caller-provided `source_id`. It queues one durable Crawl4AI page job. The worker enforces HTTPS, rejects credentials and non-public DNS addresses (except an explicitly configured egress CIDR), rechecks DNS, constrains redirects and requests to the same host, and requires Crawl4AI's robots-policy confirmation. It stores Markdown by content hash and attaches excerpt candidates as pending evidence; Markdown, manifest and evidence JSON are job artifacts. This is an operator assertion of authorization, not an automated terms-of-service or rights check; scientific claims and reuse rights remain pending review. No page was fetched during automated tests.

`POST /projects/{id}/assets/commons` requires `allow_network:true` and `allow_download:true` plus one selected Commons search candidate and a new asset ID. It downloads only HTTPS PNG/JPEG bytes from Wikimedia upload hosts, stores the image locally with its SHA-256, attaches source and asset records to the project IR, and saves an asset/manifest job artifact pair. Candidate metadata is caller-supplied and is retained as unverified; the exact license, attribution wording and intended-use rights remain `needs_human_review`. Automated tests inject a local image result and do not contact Commons.

## Local preference profiles

Profiles are stored in the workspace SQLite database and are not synced to a cloud service. `PATCH` replaces the complete `preferences` object. Stored preference keys are `language`, `audience_profile`, `duration_seconds`, `theme`, `tone`, and `slide_density`. Profile privacy settings are fixed to `local_only: true`, `allow_network: false`, and `allow_paid_api: false`. Pass `profile_id` when creating a project; audience, duration and theme are currently copied into project metadata only when the supplied Presentation IR does not already set those fields. Other preferences are persisted for clients but do not yet affect generation. Profiles are preference defaults, not evidence or approval state.

## Source handling

Place files under `<workspace>/incoming/`. Source import resolves symlinks and rejects any file outside that directory. Bytes are copied to `source-blobs/<sha256>` and stored without modifying the input. The source record remains `unverified` unless the caller supplied a different valid state; file hashing is integrity metadata, not scientific verification.

## Limits

This is a single-user local API without authentication, OS-level sandboxing, remote bind support, MCP scopes, general web research, or multi-process SQLite queue coordination. Do not expose it through a reverse proxy. A present project IR is required before job creation; bulk research and advanced narrative/visual intelligence remain separate later phases.
