# Local Project API and Workflow — Phase 1

## Start

```powershell
npm run api -- --workspace D:\AIAutoSlidesData --port 8787
```

The API binds only to `127.0.0.1`. It needs Node.js 22.5+ for the built-in `node:sqlite` module. It uses no network research service, paid API, or credential. The database is `<workspace>/db/aiautoslides.sqlite`; the server creates `incoming/`, `source-blobs/`, and `runs/` beside it.

## Routes

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/health` | Local service status |
| `GET`, `POST` | `/projects` | List projects; create from `{title, presentation_ir}` |
| `GET` | `/projects/{id}` | Project metadata, IR revision hash, sources and current Presentation IR |
| `POST` | `/projects/{id}/sources` | Import `{source_id, file_path, type?, locator?, verification_status?}` from `<workspace>/incoming/` |
| `GET` | `/projects/{id}/slides` | Ordered slide IR rows |
| `GET`, `PATCH` | `/projects/{id}/slides/{slide_id}` | Read a slide; patch `title`, `assertion_title`, `speaker_notes`, `evidence_ids` or `elements` |
| `GET`, `POST` | `/projects/{id}/jobs` | List jobs; enqueue a render workflow (optional `{preview:false}`) |
| `GET` | `/jobs/{id}` | Durable status, stage events, result or failure |
| `POST` | `/jobs/{id}/cancel` | Cancel queued work or request cancellation at the next stage boundary |
| `GET` | `/projects/{id}/artifacts`, `/jobs/{id}/artifacts` | List project/job artifacts with hashes |
| `GET` | `/artifacts/{id}` | Download an artifact after SHA-256 verification |

API project/job/artifact IDs are generated by the server. A slide PATCH creates a new content-addressed IR revision. It does not overwrite previous IR or PPTX files; enqueue a new job to render it. Full-deck regeneration is used, and unchanged-slide hashes are not guaranteed.

## Workflow stages and gates

1. Validate the supplied Presentation IR and record its slide/source counts.
2. Inventory source verification states. This stage explicitly reports `performed:false`; it does not do web research or verify facts.
3. Create a deterministic slide takeaway/evidence-reference plan from supplied IR.
4. Probe and negotiate the local backend. PptxGenJS IR is preferred; when enabled, Slidev IR is tried after a failure or unsupported capability. Every attempt and capability downgrade is reported. Set `allow_degraded_fallback:false` to require the preferred capability set.
5. Generate PPTX and require the adapter's structural/lineage checks to pass; a failed render/QA does not advance.
6. Render PDF/PNG previews with the existing PowerPoint/Poppler preview script. `preview:false` is permitted for diagnostics but deliberately leaves visual approval unavailable.
7. Write a review package bound to the PPTX SHA-256 and set job status to `awaiting_review`; record science (`source/evidence/claim IDs`) and visual (`slide IDs`) approval separately. Both must approve the exact artifact hash before status becomes `completed`. A change request sets `revision_required`; edit the IR and enqueue a new job.
8. Persist artifacts, review records, workflow report, JSONL stage log, hashes and SQLite artifact rows. Artifacts before approval are review materials, not completed deliverables.

The workflow is local-only. Restart recovery marks interrupted `running` jobs failed with an explanation and dispatches queued jobs; `awaiting_review` jobs remain available for later approval. PptxGenJS cannot be safely interrupted during its in-process render call, so cancellation takes effect at workflow stage boundaries.

## CLI Harness

The same workflow engine is available without a long-running server:

```powershell
npm run harness -- run --input outputs\my-deck\presentation-ir.json --workspace D:\AIAutoSlidesData --preview true
npm run harness -- status --workspace D:\AIAutoSlidesData --job-id <job-id>
npm run harness -- review --workspace D:\AIAutoSlidesData --job-id <job-id> --category science --decision approve --reviewer "Name" --note "Reviewed source support" --artifact-sha256 <pptx-sha256> --reviewed-ids SRC01,E1
npm run harness -- review --workspace D:\AIAutoSlidesData --job-id <job-id> --category visual --decision approve --reviewer "Name" --note "Inspected every page" --artifact-sha256 <pptx-sha256> --reviewed-ids S01,S02
```

The CLI and REST/MCP use the same SQLite state and engine. Review APIs record a reviewer attestation; this local single-user API does not authenticate the reviewer's real-world identity. The Harness cannot prevent an agent with arbitrary filesystem access from manually creating files outside its official generation path.

## Source handling

Place files under `<workspace>/incoming/`. Source import resolves symlinks and rejects any file outside that directory. Bytes are copied to `source-blobs/<sha256>` and stored without modifying the input. The source record remains `unverified` unless the caller supplied a different valid state; file hashing is integrity metadata, not scientific verification.

## Limits

This is a single-user local API without authentication, OS-level sandboxing, remote bind support, MCP scopes, general web research, or multi-process SQLite queue coordination. Do not expose it through a reverse proxy. A present project IR is required before job creation; document parsing/research and narrative/visual intelligence are separate later phases.
