# M4 ecosystem and adapter review

**Reviewed:** 2026-11-12 · Official product/developer documentation checked; no product account was connected, no API key was created, and no slide/research content was sent to a provider.

## Decision summary

The core stays local-first and native-PPTX. A useful free/local test was completed for Slidev's editable PowerPoint exporter (results in [`M4_BACKEND_COMPARISON.md`](M4_BACKEND_COMPARISON.md)). A loopback Google OAuth PKCE test page now verifies identity and can make a read-only Slides metadata request after the user configures a Desktop OAuth client and consents. No cloud deck-writing adapter is enabled; provider outputs do not automatically preserve this repository's evidence manifest and native chart contract, and several services require API credits/subscriptions or app registration.

## Safe adapter acceptance gate

Before implementing a cloud adapter, require: (1) explicit authorization for the named account/provider and data scope; (2) no research-content upload in default runs; (3) user-visible preview and final publish/sync action; (4) stable slide/source IDs and an evidence manifest that survives export; (5) editable-object and rendered-page comparison using synthetic data; (6) documented provider costs, retention and deletion behavior; and (7) CI that never needs cloud secrets. This is a design gate for future work, not an approval prompt for the current local workflow.
