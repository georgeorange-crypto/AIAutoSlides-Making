# P1 Local Research Workflow

This is the first runnable local route across the registry: selectable-text PDF + CSV + structured architecture JSON → source ledger/storyboard → native editable PPTX → PDF/page PNGs → OOXML QA → hashed run manifest.

## Run the checked-in synthetic fixture

```powershell
npm run fixture:research
npm run workflow:research
```

The fixture PDF and bundled CSV are explicitly synthetic. They are useful for testing the pipeline only. The generated deck keeps PDF, CSV, and architecture evidence marked unverified. Outputs go to `outputs/research-workflow/`: storyboard and evidence, extracted source Markdown, PPTX, review/lineage/QA reports, PDF, per-page PNGs, and `run-manifest.json`.

## Use local files

```powershell
npm run workflow:research -- --paper D:\data\paper.pdf --csv D:\data\results.csv --architecture D:\data\architecture.json --out-dir outputs\my-research-run
```

Local CSV input is parsed only when its schema is valid. Synthetic data continues to use the default route. Unlabeled CSV passed through this workflow is explicitly treated as local, unverified input; it receives a pending `E_CSV1` ledger record and prominent verification-pending labels. No source is uploaded or overwritten. This setting does not assert that the CSV is authentic, correctly sampled, or scientifically valid.

For automated contract tests only, `--skip-preview` omits the host renderer. Normal delivery runs the preview step. The script verifies the number of generated pages, but a human must inspect every PNG; OOXML QA cannot detect font substitution, visual clipping, overlap, or factual errors.

## Actual boundaries

- PDF.js extracts selectable text, page locators, and byte/text SHA-256 values. Scanned PDFs and OCR are unsupported. Extraction is not scientific verification.
- CSV rows map deterministically to chart inputs. Native PptxGenJS charts remain editable. The current bar importer expects 2–9 categories, finite values, one unit, and per-row positive `sample_n`; it does not aggregate repetitions or estimate uncertainty.
- Architecture JSON maps to native PowerPoint shapes and connectors. It is structured input, not generated by Mermaid. SVG/Matplotlib adapters remain future work.
- The existing PptxGenJS renderer and CLI are used as the build backend. The generic Presentation IR adapter `run()` method is still pending.
- Windows preview uses PowerPoint COM and Poppler. Renderer versions and page hashes are recorded; PowerPoint version is not yet captured by the preview script.
- Docling, MarkItDown, PyMuPDF, Mermaid, Matplotlib, LibreOffice, and python-pptx are not installed/implemented in this slice. The system Python 3.10 interpreter currently fails during `site` initialization due to a broken global `.pth`; no global site-package workaround was used.
