# Evidence audit for the 11 presentation defects

Snapshot: `codex/reviewer-evidence-20261113` (2026-11-13). This matrix separates implemented hard gates from visual or semantic judgments they cannot prove. A gate is evidence that a particular failure mode is screened; it is not evidence that a deck is beautiful, correct, or suitable for its audience.

Follow-on update: formal Harness visual approval now also requires the SHA-256 of each reviewed rendered page image, matched against the run's review context, and re-hashes the stored PNG at approval time. Missing, changed, or stale page files are rejected. This closes the stale/different screenshot reference gap; it still cannot prove that a human viewed the image or that the judgment is correct.

| User-reported defect | Formal-path safeguard and evidence | Status and residual risk |
|---|---|---|
| 1. Ugly fonts and templates | The selected theme's font families and contrast are checked against emitted PPTX runs; the title must match an emitted text box and remain at least 28 pt. Layout repetition is checked from semantic signatures and emitted object geometry. See `tests/quality-audit.test.mjs` (font, contrast, title hierarchy, layout diversity) and `docs/TITLE_HIERARCHY_REPORT.md`. | **Partial.** These checks rule out some illegible or repetitive outputs. They cannot rate taste, typography pairing, image treatment, or whether a theme looks polished. Page-by-page design review remains necessary. |
| 2. Nearly empty slides with a few words | The formal plan has a non-lowerable 40-unit explanation floor; repeated copy does not pad the count. Rendered OCR also requires minimum body-text occupancy and at least two lines. See `tests/deck-gate.test.mjs` (non-lowerable minimum) and `tests/quality-audit.test.mjs` (sparse authored/rendered copy). | **Partial, with hard floors.** A passing minimum does not prove the explanation is useful or that the page uses its space well. Topic-specific sufficiency remains a human content-density review. |
| 3. Overlap and unreadably small type | Emitted OOXML text bounds and overlaps are checked; effective run sizes, including persisted autofit, must be measurable and at least 14 pt; chart text is read from chart XML; title floor is 28 pt. OCR checks body/title overflow. See `tests/layout-audit.test.mjs`, `tests/quality-audit.test.mjs`, and `docs/HORIZONTAL_TEXT_OVERFLOW_REPORT.md`. | **Strong for measured cases, not absolute.** OCR can miss text, and renderer/font substitution can differ by machine. Inspect rendered pages on the target presentation software. |
| 4. No useful images or diagrams | A full deck must materialize visuals on at least half of content pages; planned visuals must exist; visual objects/groups have minimum size and structured diagrams are checked for graph shape. Image alt text is now screened for informative lexical overlap with the slide title/assertion/body; generic descriptions or images with no shared informative terms are blocked. See `tests/quality-audit.test.mjs` (coverage, rendered geometry, size, relevant/irrelevant/generic image descriptions) and `tests/presentation-harness.test.mjs` (unmaterialized Mermaid fallback). | **Partial.** Lexical overlap is only a relevance proxy: metadata can be misleading, synonyms and visual meaning are not understood, and licensing still needs review. Human `visual_support` review is still required. |
| 5. Architecture as meaningless boxes and arrows | Architecture validation requires named components, distinct directed action relationships, explicit entry/output, connected paths, and every node on an entry-to-output path. Invalid graphs are rejected before rendering. See `tests/presentation-harness.test.mjs` and `docs/ARCHITECTURE_LOGIC_GATE_REPORT.md`. | **Structural safeguard only.** Valid topology does not prove the represented system or causal explanation is true. Human `diagram_logic` review remains required. |
| 6. No agenda, sections, or narrative organization | Full-deck plans require an agenda, a titled transition for each section, assigned content, per-slide roles and a page map; the approved page map is bound to rendered headlines. See `tests/deck-gate.test.mjs` and `tests/quality-audit.test.mjs` (agenda, transition, assignment and roadmap). | **Enforced for declared structure.** The system cannot prove the chosen outline is the right story or that transitions communicate the intended logic. |
| 7. Assistant-to-user language in the presentation | Pattern checks inspect visible slide text and speaker notes for common direct-address and conversational prompts. See `tests/quality-audit.test.mjs` (English/Chinese voice and notes) and `tests/presentation-harness.test.mjs` (formal-path regression). | **Partial.** Novel paraphrases can escape pattern checks, and ordinary research narration must remain allowed. Human `presentation_voice` review is required. |
| 8. Opaque Chinese or long English passages in Chinese decks | Language checks block substantial English-dominant blocks and aggregate multiple shorter fragments; reviewer records include `language_clarity`. See `tests/quality-audit.test.mjs` (single and split English blocks). | **Partial.** Readability, jargon, awkward translation and the need for a technical English term require a fluent reader's judgment. |
| 9. Same template repeated throughout | Full-deck checks detect repeated composition signatures, low signature variety, dominant signatures and repeated measured object geometry even if plan labels differ. See `tests/quality-audit.test.mjs` (alternating and geometry-only repeated templates). | **Partial.** It detects geometry/composition repetition, not every repeated color, typography or illustration style; deliberate recurring grids may also be appropriate. Human `layout_variety` review remains required. |
| 10. Tiny clutter and defensive caveats everywhere | The 14 pt text floor covers measured visible OOXML runs; caveat checks block stacked, repeated and deck-wide disclaimer-style clauses. See `tests/quality-audit.test.mjs` (small text and caveat overload). | **Partial.** Phrase matching cannot decide whether an uncommon disclaimer is useful, and it does not identify every kind of irrelevant microcopy. The reviewer checks caveat relevance. |
| 11. Wrong allocation of depth and detail | Plans declare topic depth; standard priorities require at least two core pages and deep priorities at least seven. Each topic also declares distinctive `priority_terms`; the full-deck audit blocks any mapped core page whose title, assertion and visible elements match none of those terms, and reports matched terms per page. It still checks page/time shares, explanation stages and repeated filler. See `tests/deck-gate.test.mjs` and `tests/quality-audit.test.mjs` (topic-to-page alignment, priority depth, stage and time allocation). | **Partial.** Keyword overlap catches obviously unrelated tags but can be satisfied by name-dropping; it does not prove the priority terms represent the user's real priorities, the argument is correct, or explanation is progressive. Human `emphasis_depth` review remains required. |

## What the evidence supports

The repository has deterministic, adversarial regression coverage for many observable failure modes in the formal Harness. A local `runPresentationWorkflow` end-to-end run using `examples/phase1/pptxgenjs-ir.json` rendered three PNG pages with PowerPoint 16.0 and Poppler 26.07.0 and returned per-slide hashes; each reported hash matched the PNG bytes and all three pages were opened for visual inspection. This workflow invocation exercised real rendering and critique but did not use the CLI's required approved deck plan and did not record human approval. The synthetic fixture correctly remained `awaiting_review`; the available quality plan produced eight blockers, including a 12-unit explanation, 1.00% body-text occupancy, missing agenda, insufficient priority depth, OCR chart-collision findings, and a thin/low-density ending. The screenshots show a sparse cover and an oversized ending callout; visual inspection suggests the chart labels are legible despite the OCR collision findings, so those findings need a calibrated false-positive check. This is evidence that the quality path rejects this known weak fixture, not evidence of quality for arbitrary user decks. The exact PPTX hash was `ab6b407b9191fbfe5ff0387b14b24ca615bc3fd4baa76f2902ed68e4e0bf7534`; page hashes were S01 `71026a65a28155bca3b73ef00cbed248611dd2238b1534472f3e8bf24694978c`, S02 `3a8be0e8ee979f6b27751d4de6475d15983890234012a2d2f37adbe455229ca7`, and S03 `3d5b086e640512941b76a8564d8766d2c6525b690330c2c550b3f44ea10df8ca`.

The image relevance screen passes relevant descriptive alt text, blocks a sufficiently descriptive unrelated image and blocks generic alt text in the adversarial test. Priority-topic matching now requires distinctive topic terms and checks each mapped core page's actual title, assertion, and visible copy; the adversarial test verifies that unrelated mapped pages and generic stop words are rejected. The full test suite passed 367 tests, skipped 11 optional-tool checks, and failed 0. `npm run validate` passed with three source/sample-size warnings; `npm run build` generated a seven-page demo, `npm run qa` reported seven editable-text slides and one native chart, and `npm run preview` rendered all seven pages using PowerPoint 16.0 / Poppler 26.07.0; all seven PNGs were inspected. This representative CI demo is synthetic and does not validate arbitrary user decks.

No current evidence supports a claim that all 11 defects are completely solved or that every generated deck will be beautiful. The strongest remaining gap is the distinction between **structural compliance** and **semantic/design quality**: the system can enforce measurable floors and require a page-specific human review record, but it cannot authenticate the reviewer or independently prove that a visual is relevant, an explanation is clear, or the narrative gives the right topic the right depth.

## Next implementation target

Next, calibrate OCR chart-overlap findings against manually inspected rendered pages, then test priority-term matching against representative Chinese and English research deck plans to quantify false positives and name-dropping bypasses. The lexical screens catch obvious mismatches but can be evaded by name-dropping; a matching image hash proves which bytes a review record references, not that a person opened them or that a subjective judgment was sound.
